# desktop

`ili9341-lcd-secondary-screen` 的上位机（命令行，`clap` 解析参数）：把整个 Wayland 输出**缩放**成 320×240，
按 16×16 分块 diff，只把变化的块走串口推给板子。

- 抓屏：`../lib/screen-capture-wayland-wlr`（`zwlr_screencopy_v1`，wlroots 系：Hyprland / Sway）
- 串口：`serialport 4.10`（关掉 `libudev` 特性，走 sysfs 枚举，不需要 udev 头文件）
- 协议与固件侧常量必须一致，见 [`../ili9341-lcd-secondary-screen/README.md`](../ili9341-lcd-secondary-screen/README.md)

## 用法

```bash
cargo run -- --list                  # 看有哪些输出与串口
cargo run -- --verbose --fps 15      # 每帧打一行，15 fps
cargo run -- --serial /dev/ttyACM1
cargo run --release -- --serial /dev/ttyACM0,/dev/ttyACM1   # 双口逐块并行
cargo run --release -- --fps 15     # 缩放是逐源像素的，release 才跑得满帧
```

| 参数 | 缺省 | 说明 |
|---|---|---|
| `--list` | | 列出输出与串口后退出 |
| `-v, --verbose` | | 每帧打一行（帧号、脏块数、实际发出的块数） |
| `--output NAME` | 第一个输出 | Wayland 输出名 |
| `--serial A,B` | 全部 USB 串口 | 逗号分隔（也可重复给）；所有口逐块并行抢发，`ttyACMx` 会自动换成 by-id 稳定路径 |
| `--baud N` | `2000000` | USB CDC 链路会忽略；走 UART0 时必须与固件一致 |
| `--fps N` | `10` | **初始**目标帧率，运行中按板子上报的 `busy_ms` 自动调整（上限 30） |
| `--cursor` | 关 | 把鼠标指针抓进帧里 |

分辨率不在上位机配：连上口后等板子上报几何信息（面板宽高 + 采样倍数），收到就回确认（`0x06`），
**确认之前不开始抓屏**；板子没收到确认会每 500 ms 重报一次。采样倍数是固件侧的常量
（`ili9341-lcd-secondary-screen/src/link.rs` 的 `SCALE`），改成 2/4 可把像素数据降到 1/4、1/16。

每秒一行状态：

```
[usb-jtag] 35 captured (11.3 fps), 33 sent (9.9 fps), target 15, board 12 fps (busy 1 ms), 6 dirty,
    900 tiles (43 KB/s, 41% of raw), send 1422 us (max 127898), loop 60436 us, capture 8858 us
    | usb-jtag 13.0 t/s 22 KB/s 4 ms/t
```

前两个是抓屏/发送的帧率，`% of raw` 是压缩比，`send` 是写完一帧的耗时（数据不等应答，
写完即推完），`loop`/`capture` 是抓屏周期与库报告的抓屏耗时；
末尾每个口一行：块率、吞吐、每块平均耗时——双口时看这里就知道谁在干活。

`dirty` 是当前帧与上一帧不同的 16×16 块数；安静桌面上第一秒之后基本都是 `0 dirty`，
只有光标、时钟、窗口标题在动时才传几块——这就是局部刷新。

## 动态帧率

板子每帧都在应答里带回 `busy_ms`（收到本帧第一批 → 画完最后一批的耗时），上位机据此算它的能力上限：

```
target = clamp(1000 / busy_ms × 0.8, 1, 30)
```

只用到八成，剩下两成让链路空转，队列才不会堆。调整**慢升快降**（每 250 ms 最多加 1，降则立刻降），
`busy_ms` 先做 0.7/0.3 的指数平滑，免得「一帧 2 块」和「一帧 300 块」把目标来回甩。

```抓屏线程：抓屏 → 缩放 → 分块 diff → 把整帧的块放进队列（上一帧没写完就丢这一帧）
每口一线程：从队列取一块、发一块（只管发不等应答）；写完最后一块的线程放行下一帧
```

抓屏永远不等串口，串口也永远不等抓屏。槽位里最多一帧，延迟恒定在一帧以内；
发送跟不上时丢的是旧帧。

多口并行**逐块自由抢**：粒度小到一块，慢口拿一块丢一块也不拖快口、不拖帧尾。
数据不等应答，板子状态（帧率/忙碌毫秒）只从控制命令拿——活口里序号最小的口每
500 ms 顺路 ping 一次；ping 连着两次不通就判死，下一帧整屏重推补上它丢在途里的块；
死口先 ping 原连接复活，重开串口会经 DTR 复位板子，要等其它口也全挂才试、且至少隔 5 s。

抓屏节奏按目标帧率做闭环（`周期 - 抓屏耗时 - 处理耗时` 的余数睡掉），赶不上就不睡也不补帧。

## 控制命令

除了数据命令（`0x01` 传 tile），还用到两条控制命令：

- `0x03` 清屏：启动时先发一次，免得上一轮残留的像素留到第一帧
- `0x02` 查询：空闲时每 500 ms 发一次；推流中由序号最小的活口顺路发，帧率反馈不断流

调试打包与应答字节：`SCREEN_DEBUG=1 cargo run -- --verbose`。

## 缩放

每帧把整幅输出（2457×1536 之类）缩到 320×240，用 `fast_image_resize 6` 的
`ResizeAlg::Convolution(FilterType::Box)`（面积平均）。不用线性/三次插值：7.7 倍缩小下插值采样
会让等宽字体的一像素竖线整条消失。

- 抓屏缓冲直接 `Image::from_slice_u8` 借过去，不复制整帧
- `mul_div_alpha = false` 必须显式关掉：抓屏是 Xrgb8888，X 字节常常是 0，走 alpha 预乘会把整屏算成黑色
- 缩放结果（RGBA）再一趟转 RGB565，然后就只剩分块 diff

debug 构建的缩放仍是纯软件逐像素，实测 3 fps 左右，`--release` 快一个量级。

## 注意

- 抓的是**整幅输出**再缩放：库只提供整输出抓取，区域版每帧都要重连 Wayland、还要 spawn `wlr-randr`。
- 输出缩放 > 1 时抓到的缓冲是**逻辑**尺寸（2457×1536），缩放比按逻辑尺寸算，画面上就是整个桌面。
- 一条消息一块 tile、只发不等应答（板子对数据不回 ACK，丢了就丢了）：实测单 CDC 稳态约
  **280 KB/s**，双口（CDC + CH343）约 **320 KB/s、板子实绘 24 fps**——粒度小到一块后
  UART 在并发推流下丢的那点块由后续帧覆盖，慢口净贡献为正。
- 每块 tile 先做游程压缩，压不动就原样发（状态行的 `% of raw`）。实测文字/界面内容约 **30–58%**，
  照片视频退回 100%。整屏 300 块由 264 ms 降到约 115 ms。
- 按压缩后折算：一帧 90 块以内可以稳在 24 fps，20 块以内可以跑满 30 fps。
- 某个口挂掉只降级不退出：活还回游标给别的口接手，全挂了才报错；单口挂掉后下一帧整屏重推补块。
- `--list` 里的分辨率来自 `wlr-randr --json` 的 mode（物理尺寸），与抓到的逻辑尺寸可能不同；
  越界的报错以 `run` 打印的那条为准。
